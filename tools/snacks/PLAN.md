# 零食/饮料识别标注 · 实现方案

> 状态：**已实现**（2026-11-26）。仅针对当前这一关，不追求跨关卡泛用。
> 目标：抓一张手机截图，把棋盘上所有零食/饮料框出来并标名字，同时标出右上角带中心点的圆圈（退出按钮）；顾客气泡里的商品图不算。

---

## 一、实机观察（1080×2400）

| 区域 | 位置 | 说明 |
| --- | --- | --- |
| 商品带 | y ≈ 1224~1575 | 零食在上排，饮料在下排；本关所有商品都在这里 |
| 顾客气泡 | x ≈ 480~735, y ≈ 1810~2000 | 里面有冰红茶/矿泉水，和棋盘商品是同一套图，**必须按区域排除** |
| 手势图标 | x ≈ 530~650, y ≈ 1480~1610 | 白灰色，会遮住右侧蓝色饮料的一部分 |
| 退出按钮 | x ≈ 977~1021, y ≈ 151~194 | 右上角白底圆角条里的「同心圆 + 中心点」，单独识别，不计入商品 |

本关出现 6 类商品：瓜子、花生、八宝粥（零食）、冰红茶、矿泉水、啤酒（饮料）。
截图 `outputs/snack_frame_5.png` 里共 9 个商品，其中 1 个被手势遮挡。

## 二、方案选型

| 方案 | 结论 |
| --- | --- |
| 读控件树 | 不可用：游戏是 canvas，`uiautomator dump` 里没有商品节点 |
| 颜色阈值 / 轮廓分类 | 不可用：袋子/罐子/瓶子颜色跨度大，同类不同款容易混 |
| 训练检测模型（YOLO 等） | 杀鸡用牛刀：本关只有 6 种固定 sprite，样本采集和标注成本远高于收益 |
| **彩色模板匹配 + 最小外接矩形限定** | **选用**：sprite 固定、缩放固定，匹配分区分度极高；ROI 限定后气泡里的同款图不会被误检 |
| UI 按钮检测 | 退出按钮也是固定图标，同样用模板匹配（单独模板 + 右上角 ROI），不参与商品计数 |

实测模板匹配分：干净样本 1.000，同款不同位置 0.987，**被手遮挡的矿泉水 0.876**，阈值取 0.75 有足够余量；退出按钮模板自匹配 1.000，阈值 0.85。

## 三、识别流程

1. **抓图**：复用 `tools/common/screen.py` 的 `grab()`（`adb exec-out screencap -p`）。
2. **求商品最小外接矩形**：取 y=1040~1150 的米色空白估计背景色；在 y=1150~1700 的商品带内做颜色差 + 闭运算 + 连通域，取所有前景块的最小外接矩形，外扩 20px。气泡在 y>1800，天然落在矩形外。
3. **模板匹配**：`catalog.json` 记录 6 个模板的名字/类别；在矩形内对每个模板跑 `TM_CCOEFF_NORMED`，贪心取局部极值，跨模板 NMS 去重。
4. **兜底**：矩形内没被模板命中的彩色前景块标为「未知商品」，按宽高比粗分零食/饮料；低饱和的白灰手势图标被过滤。
5. **退出按钮**：在右上角 ROI 用 `templates/exit_button.png` 单独匹配，紫色框标「退出按钮」，不计入商品数量。
6. **标注**：橙/蓝/红粗框标商品 + 中文编号名称，紫色标退出按钮；匹配分 <0.92 的商品加「（遮挡）」；顶部写零食/饮料/总数/退出按钮状态。日志只给汇总文字，不输出坐标，也不写 JSON 文件。

## 四、文件与用法

```
tools/snacks/
  PLAN.md              本方案
  quick.sh             统一入口：默认自动点击；--once 为标注
  snacks_vision.py     识别 + 标注（供标注与自动点击共用）
  snacks_auto.py       固定顺序自动点击
  add_template.py      给本关补新商品模板
  catalog.json         商品模板 -> 名称/类别
  templates/*.png      本关 6 类商品 + 退出按钮 + 积分商店叉号 + 开始游戏按钮 + 助力礼包 No thanks + 入口页真香摆摊日记页签截图样本
outputs/
  snacks_annotated.png 标注图（固定路径，覆盖更新；唯一产物）
```

```bash
conda activate big_deal
tools/snacks/quick.sh                    # 默认：固定顺序自动点击（1 轮 = 10 步）
tools/snacks/quick.sh --rounds 3         # 完整流程重复执行 3 轮
tools/snacks/quick.sh --once             # 只标注：实时抓图
tools/snacks/quick.sh --once --image outputs/shot.png --show-roi
```

新增本关商品：

```bash
python tools/snacks/add_template.py --image outputs/shot.png \
    --file chips.png --name 薯片 --category 零食 --box 100 1220 180 1360
```

## 五、自动点击

按固定顺序执行：`冰红茶 → 矿泉水 → 冰红茶 → 啤酒 → 矿泉水 → 啤酒 → 瓜子 → 花生 → 八宝粥 → 退出按钮`。

- 前 9 步每次点击前**重新抓图识别**目标位置，因为商品位置会变；同名多个时参考上一次点击位置，优先选离得远的块（只有一个候选时直接点）。找不到时最多重试 4 次（每次间隔 0.5 秒），仍找不到则中断并发失败通知。
- 退出按钮**不识别**，直接点固定坐标 `(999, 172)`（1080×2400 基准）。
- **只在开局调用** `handle_interrupts()`，按**固定顺序循环**：入口页「真香摆摊日记」页签（点中心、等 6s） → 积分兑换商店（红叉） → 游戏主界面「开始游戏」 → 助力礼包（No thanks） → 广告页（back）。入口页在最前；之后顺序不能颠倒：先关商店，再点开始游戏，然后关掉开始游戏后新弹的礼包，最后处理可能出现的广告页。一轮里发生过操作就再按同顺序走一轮；直到某一轮五项都没命中，说明已进入关卡，立刻开始点击零食饮料，**中途不再检测任何界面**（最多 6 轮）。
- **游戏入口页**：用 `templates/entry_tab.png` 匹配「真香摆摊日记」页签（裁 x640~1040 / y980~1160），命中点中心 `(840,1070)` 并等 6 秒。实测入口页自匹配 1.000，其它页面最高 0.274，阈值 0.85 不误判；实机点击后进入游戏并弹出积分商店。
- **助力礼包弹窗**：用 `templates/gift_no_thanks.png` 匹配「No thanks」按钮，命中就点掉并等 1 秒。实测礼包页自匹配 1.000，其它页面最高 0.420，阈值 0.85 不误判。
- **游戏主界面**：识别橙色「开始游戏」按钮（`templates/start_game.png`，只裁按钮本体，不含底部省市标签），命中就点一下并等 4 秒（原 5 秒，按用户要求减 1 秒）。按钮有动画/省市标签变化，阈值降到 0.6：两次实机主界面得 0.700 / 1.000，关卡画面 0.182、商店页 0.215、礼包页 0.210、广告页 0.136，不会误判。
- **看广告页面**：判据依次为「整屏近纯白（白像素比例 >0.85）」→「右上角固定退出按钮消失」→「控件树出现 WebView」，命中就直接按返回键并等 1 秒。游戏关卡右上角退出按钮始终存在，**它没了就按广告页处理**——这条最可靠，广告内容加载完后白屏/WebView 判据都会失效。若一次返回没回到游戏，开局的循环会再按同顺序检查并继续返回，直到退出按钮重新出现。实测广告页白屏比例可低至 0.012、无 WebView，但退出按钮确实消失。
- **积分兑换商店**：用 `templates/shop_close.png` 在右上角区域匹配红叉，命中就点掉并等 1 秒。实测商店页自匹配 1.000，普通关卡画面最高 0.364，阈值 0.85 不误判。
- 每次点击后等 1 秒；点完八宝粥后等 2 秒；**退出按钮点完等 2 秒**（`EXIT_WAIT`，给下一轮转场留出时间）。
- **`--rounds N`**（默认 1）：完整流程重复 N 轮。每轮都重新跑开局检测并重置点击位置记录；某轮中途失败会带上轮号（「顺序点击失败（第 X 轮）：…」），不再继续后续轮次。全部完成后发一条简短通知「顺序点击完成（N 轮）」。

```bash
tools/snacks/quick.sh                   # 执行 1 轮（10 步）
tools/snacks/quick.sh --rounds 3        # 完整流程执行 3 轮
tools/snacks/quick.sh --dry-run         # 只打印顺序与轮数，不点击
tools/snacks/quick.sh --no-notify       # 不发通知
```

已用当前关卡截图验证 9 个商品目标都能找到，退出按钮固定坐标与识别中心一致；助力礼包「No thanks」与跳广告后返回已实机验证。

## 六、已知限制

- 模板来自当前关卡当前分辨率，换关卡/换分辨率需要补模板（`add_template.py`）；脚本按比例缩放模板，分辨率变化不大时可继续用。
- 若商品被遮挡超过一半，模板匹配分会掉到阈值以下，此时靠「未知商品」兜底框出，但自动点击不会点「未知商品」。
- 自动点击不处理复活/通关弹窗等中途状态；遇到异常会停手并通知。
