## 一、需求与本次理解

1. **开局解锁槽位**：点画面中部左侧绿色 `+` → 弹窗 → 点「免费使用」看广告 → 返回游戏 → 传送带槽位 +1。可循环多次。
2. **放入桶**：点第一排的桶，桶进入传送带槽位、向画板洒沙，其它桶上移补位。
3. **选桶规则**：**批量**选第一排中**颜色不重复**的桶（每种颜色最多一个），优先不在槽位中的颜色，依次点击提升效率；若第一排颜色都已在槽位中（或连续同色 5 轮），则随机兜底。
4. **终止条件**：遇到**复活**或**通关**弹窗立即停止，不做任何点击。

### 用户拍板（2026-11-23）
1. 解锁：**一直解锁到加号消失**（代码保留 `--max-unlock 12` 作防死循环上限）。
2. 选桶兜底：**同一槽色连续 5 轮**就随机选一个（`--repeat-limit 5`）。
3. 复活/通关模板：**均已实机抓取并验证命中即停、0 点击**（复活 2026-11-23 早、通关当晚）；模板未放入前相关检测静默跳过。
4. 目标：**单关打通**。
5. 在当前状态下继续（不重置关卡）。

### 受控实验（已做）

1. 点加号 `(197,1325)` → 弹出「解锁槽位」弹窗：紫色桶图标 +1、文案「传送带上增加一个槽位」、绿色 **「免费使用」** 按钮（中心约 `(543,1515)`）、右上角红色 X（约 `(944,600~665)`，本轮未成功点中，实施时需模板精确标定）。
2. 点「免费使用」→ 跳京东广告页；控件树有 `text="点击立即返回"`，bounds `[880,663][1045,698]`，`clickable=false`，用 `input touchscreen tap` 点击有效（与 ring/slots 经验一致）。
3. 返回后槽位计数 `0/6` → **`0/7`**，解锁成功；加号仍在，可继续解锁。
4. 点第一排桶 `(120,1490)` → 桶消失、下一排上移补位，画板得分/连击，槽位计数短暂 `1/7` 后归零（桶被处理后释放）。
5. 再点白桶 `(730,1490)` → 同样流程；槽位行中央短暂出现带数字的彩色圆形（青 `197`、白 `725`），是「正在处理的桶」，不是稳定占用。

### 关键结论

- **槽位是动态的**：计数表示正在处理的桶数，颜色只在槽位行中央短暂可见。因此「槽位颜色」识别必须在画面稳定后抓图，且要有「最近点击颜色」作为兜底代理（见第六节）。
- 第一排桶列数/尺寸随关卡变化（155 关 5 列小桶，156 关 4 列大桶），必须用连通域自适应检测，不能固定列坐标。
- 广告返回、安全验证、通知等执行逻辑可直接复用 `tools/slots/slots_auto.py`。

## 五、感知层方案

1. **抓图**：`adb exec-out screencap -p`；坐标按 1080×2400 比例缩放。
2. **第一排桶** `detect_first_row(img)`：**连通域自适应检测**（列数/桶尺寸随关卡变化）。掩码 = 高饱和 S>60 或暗色 V<90，排除米色背景/空槽底，用 bbox 顶部 y∈[1330,1480] 限定只取第一排；**桶色取桶口内部**（bbox 顶部 +20~70px）中位 HSV。已验证 155 关（5 列小桶：蓝/白/青/黑/紫）与 156 关（4 列大桶：绿/绿/绿/黑）。桶数字不识别。
   - **黑桶修复（2026-11-23）**：黑桶内壁 (H0 S20 V38) 曾被 `v<45` 的暗色过滤排除；现改为只排除 `v<12` 的纯黑描边，黑桶正确归 `black`。
   - **白桶内壁统一**：(H0 S21 V216) 在通用色表差 1 落到 `gray_light`，已在 `hue_name` 包一层修正归 `white`（与纯白 H0 S0 V255 一致）。
   - **锁定桶排除**：带问号的未解锁桶底 (H109 S114 V179) 归 `unknown`，不参与颜色决策；容差收紧到 (5,18,18)，避免与空槽底 (115,87,161) 混淆。
3. **槽位颜色** `detect_slot_colors(img)`：槽位行 ROI（y≈1160~1236，避开两侧橙箭头与底部橙边）内做连通域，排除米色背景(H14~32/S>80)与空槽深蓝(H104~126/S45~130)，取中位色。实测稳定识别 `蓝/白` 等。每轮 `wait_stable` 后抓图。
4. **加号/免费按钮**：绿色加号用颜色+轮廓（约 20×45 像素，中心 `(197,1325)`）；「免费使用」用颜色+模板匹配（绿色长条，中心约 `(543,1515)`）。弹窗标题「解锁槽位」作为弹窗存在的判据（模板匹配）。
5. **终止弹窗**：`revive_banner.png` / `victory_banner.png` 模板匹配（阈值 0.8），命中即抛 `TerminalState`，主循环捕获后停止，**不点任何东西**。
6. **广告页/安全验证**：复用 slots 的 `dump_ui` / `find_text_node`，匹配 `点击立即返回` / `安全验证`。
7. **标注图**：绿色粗框 + 黄底大号「1」标出本轮要点的桶；其它桶蓝色圈号；槽位颜色文字标注；加号/免费按钮虚线框。沿用现有醒目风格。

## 六、决策层方案

### 开局解锁（用户定稿：解锁到加号消失）

```
循环（上限 --max-unlock 12，仅防死循环）：
  抓图 → 终止弹窗？→ 停
  有加号？→ 点 → 等「解锁槽位」弹窗 → 点「免费使用」→ watch_ad_return
  → 回游戏 → 下一轮；加号消失 → 完成
```

### 主循环（每轮）

```
抓图
  → 复活/通关弹窗？ → 停（不点任何东西）
  → 广告页/安全验证？ → 走 watch_ad_return / wait_for_user
  → wait_stable 等画面稳定
  → detect_first_row + detect_slot_colors
  → 批量选桶（每种颜色最多一个）：
       同一槽色连续 ≥ --repeat-limit(5) 轮 → random.choice(第一排)（单桶兜底）
       cand = 第一排中 color ∉ slot_colors 的桶，按颜色去重、从左到右
       cand 非空 → 取前 --batch-size 个（0=不限）
       cand 为空 → 颜色去重后打乱，取前 --batch-size 个
  → 依次 adb tap(x, y)（间隔 --batch-gap 0.15s；
     批次内每次点击前复查终止弹窗）→ 等稳定 → 下一轮
```

**关键事实（2026-11-23 实机验证）**：第一排位置是固定的（关卡 156 为 4 列 x≈226/434/643/851），
点某个桶只在**该位置补位**、其他桶坐标不变。因此同一张图上选出的多个不同色桶可以
依次快速点击，无需每点一次重新抓图——这是批量点击提升效率的基础。

### 兜底与停止

- 连续 3 轮识别不到第一排 → 停止（可能已通关或界面异常）。
- `--max-clicks` / `--max-seconds` 到限停止；`Ctrl+C` 可中断。
- 结束手机通知复用 slots 的 `notify_phone`（标题「沙画收集」）。

## 九、风险与边界

- **槽位颜色是瞬时状态**：点桶后桶很快处理完并释放槽位，若只在动画期抓图会误判；必须等稳定，并保留「最近点击颜色」兜底。
- **弹窗 X 坐标未标定**：本轮探索一次误触进了广告（已安全返回），实施时要用模板确认关闭按钮，避免盲点。
- **通关模板已实拍**（2026-11-23 晚，关卡 156 通关界面）：`templates/victory_banner.png` 取「恭喜通关!」橙红标题 x180~900/y455~625；自匹配 1.0 / 普通 0.25 / 复活 0.36 / 解锁 0.29，阈值 0.80 不误判。自动模式实测 1 秒停手、0 点击。
- **广告改版**：返回控件文案/位置变化会破坏解锁流程，保留人工兜底与超时返回键。
- **合规**：仅模拟点击，不修改游戏数据、不绕过付费；账号风控由用户自行判断。
