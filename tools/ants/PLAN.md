# 搬砖大战（蚂蚁搬像素）辅助方案

## 工具范围（用户确认）
**只检查弹窗、槽位、第一排候选块，不检查上方像素画。** 不做前沿识别、不数格子、不读块上数字、不考虑队列前移。

## 识别方案
- 固定几何（1080×2400 基准）：槽位中心 x=161/350/539/729/918、y=1709；第一排候选块 y≈1897、x=209/375/540/705/871。其他分辨率按比例缩放。
- 槽位占用：下排 5 个槽位坐标固定（x=161/350/539/729/918、y=1709），逐个用固定窗口判断；窗口内彩色像素（或暗像素 V<115）占比 >20% 即视为占用，并按占优像素组的 HSV 中位数识别槽位颜色。**不要只对米色空槽做连通域**——那样被占用的槽会整块消失；也不要漏掉黑块（V≈43、S≈30 不属于彩色掩码），否则整槽黑块会被判成空槽（均已修复）。
- **第 6 槽（广告解锁位）**：在第 5 槽正上方 (918,1514)。解锁前是蓝色「解锁」按钮，解锁后变米色空槽或被占用块。检测时先判该位置是否已解锁：`bluish(H90~120 占比)≥0.5` 是按钮、不算槽；否则要求有内容（beige/colored/dark 任一占比 >0.30）才算槽，纯背景和未解锁按钮都不误判。曾因只扫 5 个槽漏掉这个解锁空槽，误判「槽位已满」导致黑块选不出来（已修复）。
- 候选块：只识别第一排（y 1810~1990），按颜色分类，不读数字。掩码必须覆盖四类：高饱和彩色 / 深色黑块（V<75 且 S<110）/ 粉色（H≥150、S>45）/ 中低饱和灰紫（100≤H<150、S>40）。米色背景 H≈21 S≈60，靠 H 区间排除；只用「S>95 或深色」会漏掉粉色和黑块（已修复）。
- **固定位置兜底**：掩码总会漏掉没预见的颜色（如深灰蓝 H104 S54 V90，既非 V<75 黑块也非 V>170 灰紫）。5 个候选位置固定，连通域漏掉的位置按固定窗口直接采样补齐，不再依赖掩码。但必须过两道防误检关：**白色数字像素 ≥150**（真实块 262~1551，弹窗/结算/其他游戏背景 0~26）+ **`classify_hsv` 结果非 None 且非 unknown**。实测兜底误检从 81 张截图降到 34 张且全为真实对局块。
- 红色系有两种必须分开：暗红 H≈171 S≈203 V≈156、亮红 H≈179 S≈207 V≈239。高饱和（S≥140）时用 V<190 分暗红/红；低饱和高 H 仍为粉。否则同色去重会误跳过另一种红块（已修复）。
- 颜色池用 `palette_calibrate.py` 从上方像素画标定（参考 slots 工具），结果存 `palette.json`。当前 14 色：黑/暗红/浅橙/红/深棕/青/浅棕(棕)/灰/橙/白/橄榄/橙红/绿/深绿。标定时自动检测画板 ROI、估格距、取格心众数色、KMeans 聚类，并列出 `issues`（unknown 或多个簇被归成同一类）；修 `classify_hsv` 后应做到 `issues` 为空。
- **块主体采样 `main_color()`**：块上有白色数字和深色描边阴影，直接取全体中位数会把亮色拉暗。实测 peach 块全体中位 `[11,99,233]`（V233）被旧判据 `s<115 且 v>235` 误判成 light_brown，而高亮主体是 `[12,82,255]`。这导致槽里已有 peach 却没进 occupied、工具继续投 peach（重复色根因）。修复两层：① 采样取 V 高 60% 分层中位，避开描边阴影；② peach/light_brown 色相都≈11，改为只按明度分 `V>=225 → peach`，去掉 `s<115` 硬限制。14 色 + 20% 暗像素干扰回归零偏离。
- 解锁按钮：模板 `templates/unlock.png` 匹配，开局看广告解锁槽位。
- 弹窗：红色 X 模板匹配 + 周边亮度判据。福利弹窗（暗遮罩）点 X 关闭；复活弹窗（亮黄底）命中后立即停止。

## 决策策略
1. 复活弹窗优先级最高，命中立即停手，不做任何操作。
2. 福利弹窗命中则只点右上角红色 X，不点「领取」，下一轮重新抓图。
3. 开局看广告解锁槽位（`--no-unlock` 跳过），广告页通过 `点击立即返回` 控件返回。
4. 一次抓图批量挑多个第一排候选块（默认 3 个，颜色不在槽中），按**从左到右**的次序点击（最左的可用色优先，这解释了为何有时先选 peach 而非更靠右的黑块），不考虑队列前移。除槽位已占颜色外，还要屏蔽「已点但尚未入槽」的颜色 `--repeat-delay` 秒（默认 8），避免搬运动画期间重复投同色。冷却解除条件：**至少经过 MIN_PENDING=1.5 秒且已在槽里看到**，或满 8 秒超时。曾因「一看到在槽里就立即解除」导致入槽动画期间槽位识别抖动为空时重复投同色（连投 3 个 peach），最短保护期即为此修复。
5. 每次点击间隔 0.35s，一批点完后等 0.8s 让槽位刷新。
6. **等待上限**：连续无法决策（槽位满 / 第一排无可用块 / 识别不到槽位或候选块）超过 `--idle-timeout`（默认 20 秒，0=不限）即停止并打印当前状态；点击块或关闭弹窗后计时清零。`--max-clicks` 只限制点击数，不限制等待时长。
7. 另外保留：连续 5 轮识别不到槽位/候选块时提前停止。

## 用法
```bash
tools/ants/quick.sh --once                       # 只识别一次，输出 outputs/ants_annotated.png
tools/ants/quick.sh --dry-run --max-clicks 3     # 试运行，不真点
tools/ants/quick.sh                              # 默认：看广告解锁 + 自动搬运
tools/ants/quick.sh --no-unlock                  # 跳过解锁
tools/ants/quick.sh --max-clicks 20 --batch-size 4
tools/ants/quick.sh --no-notify                  # 结束时不发手机状态栏通知（默认发）
tools/ants/quick.sh --notify-message "搬完了"    # 自定义通知内容
```

## 结束通知
- 和 slots/parking/ring/dogs 一致：结束时用 AutoJS6 在手机状态栏发通知。
- `notify_phone()` 把 `notice("搬砖大战", 消息)` 写到临时 .js → push 到 `/sdcard/Scripts/ants_notify.js` → 用 `am start` 拉起 AutoJS6 的 `RunIntentActivity` 执行；`notice()` 是 AutoJS6 全局函数。
- 通知内容默认自动拼：`[停止原因；]解锁 N 次，点击 N 次，耗时 Ns`。停止原因涵盖复活弹窗、关卡结束、idle 超时、max-clicks、用户中断。
- `--no-notify` 或 `--dry-run` 时不发。已实测脚本推送与 AutoJS6 拉起成功。

## 已知限制
- 因为只识别第一排、且不考虑队列前移，批次内后面的块前移后可能与原坐标不一致；按从左到右直接点击，属于用户确认的简化策略。
- 出现新颜色时先跑 `tools/ants/palette_calibrate.py` 看 `issues`，再补 `classify_hsv`；不要只靠肉眼猜阈值。
- 复活弹窗出现后工具立即停止，需要用户手动点「复活」或重开本关。
